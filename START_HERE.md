# Инструкция для Codex

Реализуй полноценный веб-сервис поддержки конкурса «Креативный музей» по этому пакету. Заказчик выбрал дизайн 01 «Чистый диалог». Не предлагай заново другие направления. Визуальный ориентир — `design/selected_reference.png`.

## Прочитай до начала работы

1. `SPEC.md` — обязательные продуктовые требования и границы проекта.
2. `design/DESIGN_SPEC.md` и `design/tokens.json` — выбранный дизайн, размеры и поведение.
3. `docs/ARCHITECTURE.md`, `docs/API_CONTRACT.md`, `docs/DATA_MODEL.md` — технические договоренности.
4. `knowledge/README.md` — основной источник, ограничения актуальности и правила импорта.
5. `docs/ACCEPTANCE.md` — проверяемые критерии готовности.
6. `docs/IMPLEMENTATION_PLAN.md` — порядок реализации.

Не ограничивайся версткой, макетом или локальными заглушками. В результате должны работать серверный чат с GPT, поиск по базе, сохранение истории, авторизация администратора, FAQ, экспорты и учет расходов.

## Порядок работы

Проверь существующий репозиторий и его AGENTS.md. Если проект новый, создай структуру из ARCHITECTURE.md; если уже есть рабочая основа, сохрани ее и объясни необходимые отклонения. Зафиксируй короткий план и выполняй его по этапам. Не меняй выбранный дизайн по своему вкусу.

Сначала создай каркас, БД и миграции. Затем свяжи публичный интерфейс с сервером, подключи поиск и GPT, реализуй админ-панель. Используй реальные модели данных с самого начала. Каждый этап должен завершаться воспроизводимой проверкой. Не откладывай хранение и авторизацию на время после оформления интерфейса.

Не используй ключи из старого Telegram-проекта. Для внешнего API нужен новый серверный OPENAI_API_KEY. Если он недоступен, продолжай в явно включенном локальном DEMO_MODE, с видимой пометкой и отдельными тестовыми данными; не утверждай, что реальные API-проверки пройдены. Не делай скрытых переключений на демонстрационные ответы.

Для макета используй выбранную иллюстрацию только как референс. Интерфейс должен состоять из настоящих HTML-компонентов. Не вставляй весь скриншот вместо сайта. Маскот должен визуально соответствовать зеленому объемному персонажу и иметь шесть состояний; краткая инструкция по его ассетам приведена в DESIGN_SPEC.md.

Не блокируй разработку вопросами о несущественных деталях. Следуй принятым допущениям из `docs/DECISIONS.md`. Отсутствующие юридические тексты, финальный сезон и реальные ключи отмечай как условия публичного запуска, а остальную работу доводи до проверяемого результата.

## Что показать в конце

- Как запустить проект локально и на сервере.
- Какие функции реализованы и где проверены.
- Скриншоты живого интерфейса на 390×844 и 1440×1000, включая длинный диалог.
- Результаты проверок из ACCEPTANCE.md, список конкретных непройденных пунктов.
- Как задать ключ, пароль, сезон, контакты и лимиты.
- Как импортировать или обновить базу и скачать историю.

Не называй проект готовым к публичному запуску, если остались имитации API, обход авторизации, потеря истории, неподтвержденные правила конкурса или критические расхождения с выбранным референсом.
