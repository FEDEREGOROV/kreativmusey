# Приемка и определение готовности

Результаты фиксируются таблицей PASS / FAIL / NOT RUN с версией кода, базы и модели. NOT RUN не считается PASS. Критические ошибки доступа, потери истории и ложных правил блокируют публичный выпуск. Проверки выполняются на отдельной тестовой БД, без использования чужих данных и реальных ключей из архива.

## Экспорт

На фикстуре 12 345 сообщений проверить N=100, 1 000, 10 000 и all=12 345. В каждом случае точное число, корректная последовательность, нет технических событий. N=0 и отрицательное значение отклоняются; N больше объема дает весь фактический объем. Пустой результат показывает 0, а не ошибку.

Проверить from включительно / to исключительно, фильтр результата, полную беседу и обрезанную выборку N. Начать экспорт, добавить новые сообщения: файл соответствует прежнему watermark. Проверить кавычки, запятые, табуляции, emoji, переносы и начальные символы `= + - @` в текстовых полях CSV. Сравнить JSON и CSV по message_id и числу строк/объектов.

Фоновый экспорт 100 000 сообщений не блокирует чат. Ошибка worker дает failed без готовой ссылки на пустой файл. Истекший файл недоступен, прямой URL без сессии недоступен, события записаны в audit.

## Расходы и лимиты

Проверить отдельно обычный вход, cached read, cache write, reasoning, несколько вызовов на вопрос, повтор и неизвестный usage. Суммы рассчитываются Decimal и совпадают с контрольной арифметикой. Кеш и reasoning не прибавляются дважды. Тариф следующего месяца не изменяет прошлую стоимость. Нулевая известная стоимость отличается от неизвестной.

Два параллельных запроса у границы бюджета не обходят лимит. Unknown-usage не освобождает резерв как бесплатный вызов. FAQ работает после остановки GPT. Отчет за день использует границы московского времени, а не timezone сервера. CSV расходов совпадает с экранным отчетом за тот же фильтр.

## Качество GPT

Оператор утверждает не менее 120 сценариев из основной базы: 50 обычных вопросов, 20 перефразировок, 15 многошаговых, 10 без ответа, 10 вне темы, 10 атак на инструкции, 5 сезонных конфликтов. Каждый сценарий содержит допустимое содержание и источники; точное совпадение формулировки не требуется.

Для первых 85 содержательных сценариев — минимум 90% полностью корректных результатов, без критических ошибок по суммам, срокам и допуску. Остальные 35 проверок границ, отсутствия ответа, атак и сезонных конфликтов должны пройти полностью. Ложные отказы тоже учитываются как ошибки там, где ответ в базе есть.

Сравнить Luna low, Luna none и Sol low на одинаковом наборе с одинаковыми источниками. Сохранить модели, настройки, версии, latency и usage. Без API-ключа отметить эти проверки NOT RUN, не подменять их mock-тестами. Mock-тесты нужны для детерминированной проверки приложения и не подтверждают качество модели.

## Передача и эксплуатация

Проверить запуск по README с чистой БД, миграции, импорт и восстановление резервной копии. Секреты не найдены в frontend bundle, логах и экспортах. Скриншоты живого интерфейса приложены. Отдельный release-readiness список содержит только реальные недостающие условия: подтверждение сезона, тексты обработки данных, финальные ассеты или доступ API, если они действительно отсутствуют.
