# План реализации

Не назначать фиктивные даты и стоимость без оценки. Этапы ниже задают зависимости и результаты. Каждый этап проверяется до перехода к следующему; визуальный интерфейс не считается завершенным, пока не связан с серверными данными.

| Этап | Содержание | Результат и проверка |
|---|---|---|
| 1 Подготовка | Проверить пакет, стек и repository rules, создать конфигурацию и skeleton | Чистый локальный запуск, миграции, health, никакого API-ключа на клиенте |
| 2 Данные и права | Sessions, conversations, requests, сообщения, admin login | Интеграционные тесты принадлежности, logout и идемпотентности |
| 3 Знания | Import, исправление структуры, источники, версия, поиск | Отчет импорта, отдельный индекс, тесты сезона и rollback |
| 4 Диалог | Responses API, контекст, result validation, попытки и usage | Настоящий путь вопрос–ответ; ошибки и повторы, unknown usage |
| 5 Публичный UI | Выбранный дизайн, маскот, сообщения, ввод, FAQ | Browser QA на 360/390/768/1440, все состояния, длинный чат |
| 6 Админ | Три вкладки, фильтры, FAQ lifecycle, отчеты | Данные из БД, нет fake metrics, публикация FAQ согласована с поиском |
| 7 Эксплуатация | Export worker, бюджет, очистка, резервирование | 100k экспорт, race лимитов, restore, protected downloads |
| 8 Приемка | E2E, контентные evals, визуальная проверка | PASS/FAIL/NOT RUN отчет, реальные скриншоты, список release blockers |

## Артефакты исполнения

Codex ведет короткий implementation checklist в репозитории и обновляет его по факту. Каждому разделу P01–P10 соответствует реализованный модуль и проверка. Тестировать нужно поведение на границах, а не наличие текста в компоненте.

Обязательные unit-тесты: расчет тарифных категорий, фильтры и границы дат, выбор последних N, валидация вопроса, правила сезонного допуска. Integration: БД, транзакции и права, publish FAQ, идемпотентность и budget races. E2E: отправка и восстановление, admin вход/выход, FAQ, скачивание экспорта. Платные evals отдельно от обычного CI.

## Допустимые рабочие решения

Исполнитель самостоятельно выбирает структуру компонентов, библиотеку таблиц, cursor implementation и детали worker, если соблюдены контракт и критерии. Не просить заказчика выбрать каждую библиотеку. Отклонение от основного стека, выбранного дизайна, основной модели или объема фиксируется с причиной и влиянием.

## Перед завершением

Удалить случайные демонстрационные записи из production seed; оставить отдельные тестовые фикстуры. Проверить .env.example и README. Указать команды, которые действительно были выполнены, и конкретные результаты. Не называть отсутствие ключа технической ошибкой реализации, но честно отделить неиспытанную внешнюю интеграцию от проверенного локального поведения.
